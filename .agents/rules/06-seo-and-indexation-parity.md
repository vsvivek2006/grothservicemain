# 06 — SEO, Indexation & Metadata Parity

> **STATUS: PERMANENT / HARD RULE**  
> SEO is the primary revenue driver for Growth Service. Zero search ranking drops or indexation losses are acceptable.

---

## 1. SEO Parity — Hard Gate

Every migrated page must achieve 100% SEO parity with the current production Vite application.

### 1.1 Page Title & Meta Description
- Every page must have an explicit, descriptive `title` and `description`.
- Titles must match current keyword formulations and brand suffix (` | Growth Service`).
- Do not use generic fallback titles like "Home" or "Page" on dynamic or detail routes.

### 1.2 Open Graph & Social Sharing
Every public page must specify:
- `openGraph.title`: Matches page title.
- `openGraph.description`: Matches meta description.
- `openGraph.url`: Canonical URL of the page.
- `openGraph.siteName`: `Growth Service`.
- `openGraph.images`: Absolute URL to high-resolution brand share card.
- `twitter.card`: `summary_large_image`.

### 1.3 Canonical URL Integrity
- All pages must define an explicit canonical URL pointing to `https://www.growthservice.in/`.
- No self-referential canonical mismatches, HTTP vs. HTTPS bugs, or non-www canonical links.
- Stripped parameters: canonical URLs must omit tracking query params (`utm_*`, `ref`).

---

## 2. Structured Data (JSON-LD) Parity

Rich search snippets and local ranking depend on JSON-LD structured data.

### 2.1 Supported Schema Types
1. **Organization Schema:** Present on homepage and global layout. Includes company name, logo, official URLs, phone number, and social profiles.
2. **LocalBusiness Schema:** Present on city and location pages (`/locations/:city`, `/hub/:location`). Includes geo-coordinates, service area, and business hours.
3. **Service Schema:** Present on service detail pages (`/services/:slug`). Includes service type, provider details, and description.
4. **BreadcrumbList Schema:** Present on all hierarchical subpages.

### 2.2 Schema Validation Rules
- All JSON-LD scripts must output valid, parseable JSON.
- Test against Google Rich Results Test standards.
- Schemas must match the properties generated by the Vite application.

---

## 3. Sitemap & Robots Configuration

### 3.1 Sitemap Parity (`sitemap.xml`)
- Must contain all indexable static pages, service pages, location pages, and hub pages.
- Must list exactly 175 canonical URLs matching the Route Parity Inventory.
- URLs must be absolute (`https://www.growthservice.in/...`).
- Last modified dates (`<lastmod>`), change frequencies (`<changefreq>`), and priorities (`<priority>`) must be accurate and valid.
- Must not include duplicate URLs, redirected aliases, or 404 targets.

### 3.2 Robots Directives (`robots.txt`)
- Stored at `public/robots.txt` or served via `src/app/robots.ts`.
- Must allow crawling of all public routes for standard search engines (`Googlebot`, `Bingbot`).
- Must include LLM / AI crawler directives consistent with site policy.
- Must declare the absolute sitemap location: `Sitemap: https://www.growthservice.in/sitemap.xml`.

---

## 4. Redirects & Internal Linking

### 4.1 Redirect Parity
- All existing URL aliases and legacy paths must return HTTP 301 (permanent) or 308 redirects in Next.js config (`next.config.js`).
- Never introduce redirect chains (e.g. A → B → C). Always redirect directly to the final destination.
- Ensure no redirect loops exist.

### 4.2 Internal Link Parity
- Run automated link verification (`npm run test:links` or equivalent audit).
- 0 broken internal links allowed across the entire site.
- Links must use Next.js `<Link>` component for client-side prefetching, or standard `<a>` for external/anchor links.
- Consistent URL trailing slash handling must prevent unnecessary client redirect roundtrips.

### 4.3 Query Parameter Preservation
- Search parameters, filter criteria, and UTM tracking parameters must be preserved during navigation.
- Forms and CTAs must preserve incoming campaign UTMs when navigating to contact forms.
